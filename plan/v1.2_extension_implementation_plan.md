# 微信公众号文章导出助手 v1.2 功能扩展实施计划

> **目标版本**：`v1.1.0` → `v1.2.0`  
> **适用范围**：在保持现有零构建（Manifest V3）、纯本地无后端、且全部现有测试（`npm run test:all`）零回归的前提下，完成**内容解析精度补全（5 项）**与**导出格式及产物形态扩展（5 项）**。

---

## 1. 需求范围与边界

### 1.1 纳入本期的功能清单

#### A. 内容解析精度补全（5 项全部实现）
1. **内联语义样式保留**：在清除 `style` 前，将微信富文本中的粗体、斜体、删除线、高亮底色转为标准语义标签与 Markdown 语法。
2. **封面图与文章摘要提取**：提取 `og:image` / `msg_cdn_url` 与 `og:description` / `msg_desc`，下载封面图并写入 Front Matter / HTML / EPUB 元数据。
3. **音视频、名片、引用卡片降级保留**：可开关，将音频、视频、公众号名片、引用文章卡片转为可读的语义占位块，不再直接丢弃。
4. **微信“图片消息 / 小绿书”形态适配**：兼容轮播图 + 短文页面结构，打通全格式导出。
5. **精选评论区导出（可选开关）**：提取热评、点赞数与作者回复，追加到导出产物文末。

#### B. 导出格式与产物形态扩展（选定 5 项）
1. **一键复制 Markdown 到剪贴板（Copy MD）**：无需下载文件，直接复制清洗后的 Markdown 文本。
2. **单文件离线 HTML（Single-File HTML）**：图片全部 Base64 内联，输出独立 `.html`，双击即读且保留排版。
3. **EPUB 3 电子书导出**：复用项目内置 `JSZip`，纯前端生成符合 EPUB 3 规范（兼顾旧版 NCX）的 `.epub` 文件。
4. **WebP 图片自动转 PNG/JPG**：可选开关，在本地将微信 `webp` 图片无损转为 `png`（默认）或 `jpg`，解决旧版编辑器与阅读器兼容性问题。
5. **全页长图导出（PNG）**：通过 `optional_permissions: ["debugger"]` 按需授权，调用 Chrome CDP `Page.captureScreenshot` 导出整页高清长图。

### 1.2 明确排除项
* 本期**不做**“Markdown 图片策略扩展（自定义图床上传 / Base64 内联单 `.md` 文件）”。
* 不引入 Webpack / Vite / TypeScript 等构建工具，继续保持**零构建直接加载 `src/`** 的开发体验。

## 3. 详细实现设计

### 3.1 内容解析精度补全（`src/content.js`）

#### 3.1.1 内联语义样式保留
* **新增函数**：`preserveInlineSemanticStyles(root)`
* **调用时机**：在 `extractContent(doc, options)` 中，位于 `markStructuralHints(clone)` 之后、`el.removeAttribute('style')` **之前**。
* **实现规则**：
  * 遍历 `root.querySelectorAll('span, p, section, font, b, i, s, strike')`：
  * **跳过保护区**：若元素位于 `[data-wx-code]`、`[data-formula]`、`[data-latex]` 或 `h1, h2, h3, h4, h5, h6` 内部，直接跳过（防止标题被包成 `# **标题**` 或污染代码）。
  * 解析内联 `style` 属性（统一小写、去空白后按分号切分）：
    1. **加粗**：`font-weight` 为 `bold` / `bolder` 或数值 `>= 600`，且自身不是/不在 `strong, b` 内 → 用 `<strong>` 包裹其子节点。
    2. **斜体**：`font-style` 为 `italic` / `oblique`，且不在 `em, i` 内 → 用 `<em>` 包裹。
    3. **删除线**：`text-decoration` 或 `text-decoration-line` 包含 `line-through`，且不在 `del, s` 内 → 用 `<del>` 包裹。
    4. **高亮底色**：`background-color` 或 `background` 存在有效颜色值，且不是透明或白色（排除 `transparent`、`none`、`inherit`、`initial`、`#fff`、`#ffffff`、`rgb(255,255,255)`、`rgba(...,0)`）→ 用 `<mark>` 包裹。
  * **Turndown 规则补充**：在 `createTurndownService` 中新增 `wechatHighlight` 规则：
    * `filter: 'mark'` → 去除首尾空白后返回 `==${content}==`（兼容 Obsidian / Typora 语法；若内容为空则返回 `''`）。

#### 3.1.2 封面图与文章摘要提取
* **修改 `extractMetadata(doc, href)`**：返回对象新增 `coverUrl: string`、`description: string`。
* **`coverUrl` 提取优先级**：
  1. `meta[property="og:image"]` 的 `content`
  2. `meta[name="twitter:image"]` 的 `content`
  3. 扫描 `doc.querySelectorAll('script')` 文本，正则匹配 `var\s+msg_cdn_url\s*=\s*["']([^"']+)["']`
  4. 经过 `normalizeUrl()` 规范化，过滤占位图。
* **`description` 提取优先级**：
  1. `meta[property="og:description"]` 的 `content`
  2. `meta[name="description"]` 的 `content`
  3. 扫描 `<script>` 文本，匹配 `var\s+msg_desc\s*=\s*["']([^"']+)["']` 并执行 HTML 实体解码。
* **产物集成**：
  * `buildFrontMatter(meta)`：若 `meta.description` 非空，追加 `description: "..."`；若 `meta.coverLocalPath`（ZIP/本地化后）或 `meta.coverUrl` 非空，追加 `cover: "..."`。
  * ZIP 导出（`bundleImages: true`）与 EPUB 导出时，若 `meta.coverUrl` 存在，将其加入下载任务并保存为 `images/cover.{ext}`，同时在 `meta.coverLocalPath` 中写入 `./images/cover.{ext}`。

#### 3.1.3 音视频、名片、引用卡片降级保留
* **配置项**：`keepMediaPlaceholders: true`（默认开启）。
* **新增函数**：`convertMediaCardsToPlaceholders(root)`
* **调用时机**：在 `extractContent(doc, options)` 中，位于 `NOISE_SELECTORS` 删除**之前**（仅当 `options.keepMediaPlaceholders !== false` 时执行）。
* **替换规则**（替换为 `<blockquote data-wx-placeholder="1"><p>...</p></blockquote>`，使其免于被后续 `NOISE_SELECTORS` 清理）：
  1. **音频**：匹配 `mpvoice, mpaudio, qqmusic, .article_wx_music`
     * 提取属性 `name` / `title` / `.audio_card_title` 文本，以及时长 `play_length`（毫秒转 `mm:ss`）。
     * 输出：`> [音频] {标题}（{时长}）`（无时长则省略括号）。
  2. **视频**：匹配 `video, iframe.video_iframe, .js_tx_video_container`
     * 提取 `title` / `data-title` / `data-src` / `src`。
     * 输出：`> [视频] {标题或“微信视频”}`（如有可用链接则附带链接）。
  3. **公众号名片**：匹配 `mp-common-profile, .mp_profile_iframe, .mp_profile_iframe_wrp`
     * 提取 `data-nickname` / `.profile_nickname` 与 `data-desc` / `.profile_meta_value`。
     * 输出：`> [公众号名片] {名称}：{简介}`。
  4. **引用文章卡片**：匹配 `.appmsg_card_context, mp-common-mpaudio` 或带 `href` 的文章卡片
     * 提取标题（`.appmsg_card_title` / 链接文本）与 `href`。
     * 输出：`> [引用文章] [{标题}]({链接})`（无链接则输出纯文本标题）。
* **关闭选项时**：不调用该函数，沿用原有 `NOISE_SELECTORS` 直接剔除逻辑。

#### 3.1.4 微信“图片消息 / 小绿书”形态适配
* **新增函数**：
  * `isPictureMessagePage(doc)`：检测是否存在 `#js_image_content`、`.share_media_swiper`、`.swiper_item img`，或 `<script>` 中包含 `picture_page_info_list`。
  * `extractPictureMessageContent(doc)`：
    1. 收集轮播图：优先从 `.swiper_item img, .share_media_swiper img, #img_list img` 提取 `data-src` / `src`；若 DOM 中缺失（部分页面纯 JS 渲染），则正则解析 `<script>` 中的 `picture_page_info_list` 提取 `cdn_url` 字段并去重。
    2. 收集短文正文：提取 `#js_content` 或 `.share_notice` / `.js_share_content` 内的文本段落。
    3. 构造标准化的虚拟 `<div>` 容器：先按顺序插入 `<p><img data-src="..." /></p>`，再追加清洗后的短文正文节点，返回给统一的后续导出管线。
* **入口联动**：
  * `PING_PAGE` 的 `supported` 判定改为：`!!(doc.querySelector('#js_content') || doc.querySelector('.rich_media_content') || isPictureMessagePage(doc))`。
  * `extractContent(doc, options)`：当检测到图片消息页且常规 `#js_content` 缺少轮播图时，自动合并轮播图节点到正文顶部。

#### 3.1.5 精选评论区导出
* **配置项**：`includeComments: false`（默认关闭）。
* **新增函数**：`extractComments(doc)`
* **解析规则**：
  * 定位 `#js_cmt_list .discuss_item, .discuss_list .discuss_item`。
  * 每条评论提取：
    * `author`：`.nickname` / `.discuss_nick_name`
    * `likes`：`.praise_num`（转为数字，默认 `0`）
    * `content`：`.discuss_message_content`
    * `replies`：子级 `.reply_result` / `.discuss_extra_info` 下的作者回复数组（`{ author, content }`）
  * 过滤空评论，返回结构化数组 `Array<{ author, likes, content, replies }>`。
* **各格式渲染**：
  * **Markdown**：新增 `formatCommentsMarkdown(comments)`，若非空则追加：
    ```markdown
    ---

    ## 精选评论

    > **用户名**（👍 128）
    > 评论内容
    >
    > **作者回复**：回复内容
    ```
  * **单文件 HTML & EPUB**：新增 `buildCommentsHtml(comments)`，生成语义化的 `<section class="wx-comments"><h2>精选评论</h2>...</section>` 追加至正文末尾。

### 3.2 导出格式与产物形态扩展

#### 3.2.1 一键复制 Markdown（Copy MD）
* **消息协议**：`popup` → `content` 发送 `{ action: 'COPY_MARKDOWN', settings }`。
* **`content.js` 处理**：
  * 新增 `generateMarkdownText(settings)`（与 `exportMarkdown` 共享前半段提取与转换逻辑，但强制 `bundleImages: false`，保留原图链接，支持 `frontMatter`、`keepMediaPlaceholders`、`includeComments`）。
  * 返回 `{ ok: true, markdown, charCount, title }`。
* **`popup.js` 写入剪贴板**：
  * 必须在 Popup 点击回调中执行 `await navigator.clipboard.writeText(data.markdown)`（利用用户激活态确保剪贴板权限 100% 可用）；
  * 兜底方案：若 `navigator.clipboard` 不可用，创建隐藏 `<textarea>` + `document.execCommand('copy')`。
  * UI 提示：`已复制 Markdown 到剪贴板（共 X,XXX 字）`。

#### 3.2.2 WebP 图片自动转 PNG/JPG（通用前置处理）
* **配置项**：`convertWebp: false`（默认关闭）。
* **新增函数**（`src/content.js`）：`maybeConvertWebp(imageResult, enabled)`
* **触发条件**：`enabled === true && imageResult.ok && (imageResult.ext === 'webp' || imageResult.mime === 'image/webp')`。
* **转换实现**（纯浏览器原生 API，零外部依赖）：
  1. `base64ToUint8(imageResult.base64)` → `new Blob([bytes], { type: 'image/webp' })`。
  2. `const bitmap = await createImageBitmap(blob)`。
  3. 优先使用 `new OffscreenCanvas(bitmap.width, bitmap.height)`，若环境不支持（或测试环境无 `OffscreenCanvas`）则回退 `document.createElement('canvas')`。
  4. `ctx.drawImage(bitmap, 0, 0)` → 导出 `image/png` Blob（保留透明通道，避免透明底变黑）→ 转回 Base64。
  5. 更新返回对象的 `base64`、`mime: 'image/png'`、`ext: 'png'`，并释放 `bitmap.close()`。
  6. **容错**：任意步骤抛错（如浏览器不支持或 jsdom 无 Canvas 实现）时捕获异常并原样返回原 WebP 数据，不阻塞导出。
* **复用范围**：在 `downloadImages()` 完成后统一调用，**ZIP Markdown、单文件 HTML、EPUB 自动共享此能力**。

#### 3.2.3 单文件离线 HTML（`src/converters/html.js`）
* **暴露接口**：`window.__WX_HTML_CONVERTER__ = { buildStandaloneHtml }`（并兼容 `module.exports` 供单元测试）。
* **消息协议**：`EXPORT_HTML`。
* **导出流程**（`content.js` 的 `exportHtml(settings)`）：
  1. 调用 `extractMetadata()` + `extractContent(document, settings)`。
  2. 收集并下载正文图片（+ 可选封面图），应用 `maybeConvertWebp`。
  3. 遍历克隆正文的 `<img>`：下载成功者将 `src` 写为 `data:${mime};base64,${base64}`；下载失败者保留原始 URL 并统计 `imageFailed`。
  4. 若开启 `includeComments`，追加精选评论 HTML。
  5. 调用 `buildStandaloneHtml({ meta, contentHtml, coverDataUrl, commentsHtml })` 拼装完整 HTML5 文档：
     * `<meta charset="utf-8">`、`<meta name="viewport" content="width=device-width, initial-scale=1">`、`<title>`；
     * 内联清爽阅读 CSS（最大宽度 `760px` 居中、柔和字号 `16px/1.75`、响应式图片 `max-width: 100%; height: auto;`、代码块浅灰底与横向滚动、表格边框、引用左绿线、评论卡片样式）；
     * 页头展示标题、公众号、作者、日期、原文链接及封面图（如有）。
  6. 通过 `downloadBlob()` 保存为 `{sanitizeFilename(meta.title)}.html`。

#### 3.2.4 EPUB 3 电子书导出（`src/converters/epub.js`）
* **暴露接口**：`window.__WX_EPUB_CONVERTER__ = { buildEpubZip, serializeToXhtml, extractHeadingsForToc }`（兼容 `module.exports`）。
* **消息协议**：`EXPORT_EPUB`。
* **XHTML 良构保证（关键防踩坑）**：
  * EPUB 阅读器使用严格 XML 解析器，任何未闭合标签（`<br>`、`<img ...>`、`<hr>`）或未转义 `&` 都会导致书籍打不开。
  * 实现 `serializeToXhtml(element)`：
    * 清理不合法的 XML 属性名与非法控制字符（`[\x00-\x08\x0B\x0C\x0E-\x1F]`）；
    * 使用 `new XMLSerializer().serializeToString(node)`，或针对 HTML 容器构建标准 XHTML 片段，确保所有空元素自闭合、属性均带引号、`&` 正确转义为 `&amp;`；
    * 为正文 `h1, h2, h3` 自动分配 `id="heading-1"`、`id="heading-2"` 用于生成目录。
* **EPUB 3 标准包结构（通过 `JSZip` 打包）**：
  1. `mimetype`：内容严格为 `application/epub+zip`，**必须设置 `{ compression: 'STORE' }`**（EPUB 规范强制要求不压缩）。
  2. `META-INF/container.xml`：指向 `OEBPS/content.opf`。
  3. `OEBPS/content.opf`：
     * `<metadata>`：`dc:identifier`（UUID）、`dc:title`、`dc:creator`、`dc:date`、`dc:language`（`zh-CN`）、`dc:description`、`dc:source`、`dcterms:modified`。
     * `<manifest>`：注册 `nav.xhtml`（`properties="nav"`）、`toc.ncx`、`book.css`、`chapter1.xhtml`、封面图（`properties="cover-image"`）及所有 `images/img_xxx.ext`。
     * `<spine toc="ncx">`：指向 `chapter1`。
  4. `OEBPS/nav.xhtml`：EPUB 3 目录页（含 `epub:type="toc"`），列出文章标题及各级 `h1-h3` 锚点。
  5. `OEBPS/toc.ncx`：EPUB 2 兼容目录，保证老款 Kindle/墨水屏正常识别目录。
  6. `OEBPS/styles/book.css`：墨水屏与移动端友好的简洁排版 CSS。
  7. `OEBPS/chapter1.xhtml`：文章正文（图片路径为 `images/img_001.ext`）+ 可选精选评论。
* **输出**：生成 Blob（`type: 'application/epub+zip'`），下载为 `{sanitizeFilename(meta.title)}.epub`。

#### 3.2.5 全页长图导出（PNG）
* **权限配置（`src/manifest.json`）**：
  ```json
  "optional_permissions": ["debugger"]
  ```
* **页面准备与清理（`src/content.js`）**：
  * 新增 `prepareLongScreenshot()`（消息 `PREPARE_LONG_PNG`）：
    1. 调用现有 `preloadImagesForPrint()` 预热并校验所有图片；
    2. 注入 `<style id="wx-exporter-screenshot-style">`：隐藏侧边二维码、底部栏、推荐、评论（若未勾选）、顶部广告，固定正文主容器宽度为 `750px` 居中、纯白背景、适度内边距（`32px 28px`）；
    3. 滚动到页面顶部 `window.scrollTo(0, 0)`，等待两帧 `requestAnimationFrame`；
    4. 计算主容器 `getBoundingClientRect()`，返回 `{ ok: true, clip: { x, y, width, height }, loaded, failed, title }`。
  * 新增 `cleanupLongScreenshot()`（消息 `CLEANUP_LONG_PNG`）：移除注入样式、恢复图片原状态与原滚动位置。
* **CDP 截图与下载（`src/background.js`）**：
  * 新增消息 `CAPTURE_LONG_PNG`，参数 `{ tabId, clip, filename }`：
    1. 校验 `chrome.debugger` 可用性（若用户未授权则返回友好错误）。
    2. `await chrome.debugger.attach({ tabId }, '1.3')`。
    3. 计算缩放倍率：`const scale = clip.height > 12000 ? 1 : 2`（避免超长文章触发 Chrome 内存上限导致空白图）。
    4. 调用：
       ```javascript
       const { data } = await chrome.debugger.sendCommand(
         { tabId },
         'Page.captureScreenshot',
         {
           format: 'png',
           captureBeyondViewport: true,
           fromSurface: true,
           clip: {
             x: Math.max(0, Math.floor(clip.x)),
             y: Math.max(0, Math.floor(clip.y)),
             width: Math.ceil(clip.width),
             height: Math.ceil(clip.height),
             scale
           }
         }
       );
       ```
    5. `finally` 块中**强制执行** `chrome.debugger.detach({ tabId }).catch(() => {})`，确保任何异常都不会遗留“正在调试此浏览器”横幅。
    6. 调用 `chrome.downloads.download({ url: 'data:image/png;base64,' + data, filename, saveAs: false, conflictAction: 'uniquify' })`。
* **Popup 编排流程（`src/popup/popup.js`）**：
  1. 点击「导出长图」→ 检查 `chrome.permissions.contains({ permissions: ['debugger'] })`；
  2. 未授权则调用 `chrome.permissions.request({ permissions: ['debugger'] })`，若用户拒绝则友好提示“需要临时调试权限以截取完整长图，已取消”；
  3. 发送 `PREPARE_LONG_PNG` 给 `content.js` → 拿到 `clip` 后发送 `CAPTURE_LONG_PNG` 给 `background.js` → 无论成功失败都在 `finally` 发送 `CLEANUP_LONG_PNG` 恢复页面。
