# 发布流程手册

可复用的平台发布流程文档。换项目时把对应 MD 投给 AI，它能照着直接执行。

## 文件

| 文件 | 平台 | 用途 |
| :--- | :--- | :--- |
| `xiaohongshu-publish-flow.md` | 小红书 | 图文草稿自动化完整流程 |
| `douyin-publish-flow.md` | 抖音 | 图文草稿自动化完整流程 |
| `README.md` | — | 本文件 |

这两份文档**自包含**，不依赖本仓库其他代码。复制到任何新项目都能用。

## 怎么用

### 换项目发布时

```
1. 把 xiaohongshu-publish-flow.md 或 douyin-publish-flow.md
   连同你的内容（图片 + 标题 + 正文 + 标签）一起给 AI

2. 告诉它：「按这个流程，把这些内容存到草稿箱」

3. AI 会先标定坐标，再按步骤执行，每步截图验证
```

### 需要一起提供的

- 图片的绝对路径（或文件名 + 所在目录）
- 标题、正文、标签文案
- 一句确认：「保存为草稿即可，不要发布」

### 底层代码

两套流程共用同一套 Win32 封装。如果 AI 需要代码实现，把
`../xiaohongshu/` 下的这几个文件一并给它：

```
uiauto.py     键盘 / 鼠标 / 剪贴板 / 截屏
forcefg.py    强制窗口前台
winlist.py    枚举 Chrome 窗口
```

## 两份文档的共同前提

| 条件 | 说明 |
| :--- | :--- |
| 操作系统 | Windows（依赖 Win32 API） |
| 浏览器 | Chrome，已登录对应平台创作者中心 |
| 平台页面 | 必须已经在浏览器里打开，或至少登录态有效 |
| 权限 | 无需 cookie、无需 token、无需 API key |

**这是 UI 自动化**：AI 通过模拟真实鼠标键盘操作页面，全程不读取、不传输任何登录凭证。

## 核心原理（一句话）

用 Win32 的 `SetCursorPos` + `mouse_event` + `keybd_event` 操作**屏幕上已登录的窗口**，
文件通过 `WM_SETTEXT` 直接写入系统文件对话框，文本通过剪贴板粘贴。

## 为什么不走 CDP

已实测三条路都不通，别浪费时间：

1. 默认 profile 加 `--remote-debugging-port` → Chrome 136+ 安全策略拒绝
2. 复制 profile 再开调试端口 → Cookie 设备绑定加密，复制即未登录
3. 复制 Cookies 文件 → 独占锁，备份权限也打不开

## 两个平台的差异速查

| 项目 | 小红书 | 抖音 |
| :--- | :--- | :--- |
| 发布页 | `/publish/publish?target=image` | `/content/post/image` |
| 标题框 y | 405 | **320** |
| 保存按钮 | (1066,1342) | (1101,1300)，**先滚到底** |
| 保存成功标志 | 绿色「保存成功」 | 跳回上传页 + 未发布提示 |

## 已知限制

- **坐标会随分辨率/窗口状态变化**，每台机器首次使用都要重新标定（文档里写了方法）
- 平台改版会失效，需要按文档的「失败→修法」表排查
- 不处理登录，登录态由用户自己维护
- **永不自动点发布**，这是设计原则不是限制

## 维护建议

平台前端改版后，按这个顺序更新文档：

1. 截图确认新的元素位置
2. 更新「参考坐标」表
3. 如果有新坑，补进「失败 → 修法速查」
4. 更新文末的「最后验证」日期
